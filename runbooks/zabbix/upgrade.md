# Upgrade Zabbix (docker compose)

> **DRAFT** — not yet run end to end.

Upgrade of server, web and proxy containers, followed by stock template refresh. The server upgrades the DB schema on first start. Compose files are generated by Ansible (`docker-compose-projects` role): change image tags in the inventory, never on the hosts.

A minor upgrade (x.y.z → x.y.z+1) needs only steps 0, 2–6 and 9.

## 0. Set variables

```bash
OLD=<current version, e.g. 7.2.6>
NEW=<target version, e.g. 7.4.15>
NEW_MAJOR=<x.y of target, e.g. 7.4>
INVENTORY=<path to inventory>
ZBX_URL=https://zabbix.lan.chere.one
ZBX_TOKEN=<super admin API token>
export NO_PROXY=zabbix.lan.chere.one
```

On the zabbix host, as root (`sudo -i`; the compose dir is root-only):

```bash
COMPOSE_DIR=/opt/docker-configs/local/zabbix
BACKUP_DIR=/mnt/backup/zabbix
DB_CONTAINER=postgresql-server
DB_USER=zabbix
DB_NAME=zabbix
```

## 1. Read the upgrade notes

https://www.zabbix.com/documentation/$NEW_MAJOR/en/manual/installation → "Upgrade notes for x.y.0" and "Upgrade notes for x.y.x" for every major version between `$OLD` and `$NEW`. Also check the supported PostgreSQL range in Requirements.

**STOP** if a breaking change applies and isn't handled.

## 2. Check the images exist and pre-pull them

```bash
# zabbix host
docker pull zabbix/zabbix-server-pgsql:ubuntu-$NEW
docker pull zabbix/zabbix-web-nginx-pgsql:ubuntu-$NEW
# proxy host (as root)
docker pull zabbix/zabbix-proxy-sqlite3:ubuntu-$NEW
```

## 3. Stop server and web, dump the DB

```bash
cd "$COMPOSE_DIR"
docker compose stop zabbix-server zabbix-web-nginx-pgsql
docker exec $DB_CONTAINER psql -U $DB_USER -d $DB_NAME -c "SELECT mandatory, optional FROM dbversion;"
docker exec $DB_CONTAINER pg_dump -U $DB_USER -d $DB_NAME -Z1 \
  > "$BACKUP_DIR/pre-upgrade-$OLD-$(date +%Y%m%d-%H%M%S).sql.gz"
gzip -t "$BACKUP_DIR"/pre-upgrade-*.sql.gz && echo OK
```

Restore procedure: [restore_db_from_backup.md](restore_db_from_backup.md).

## 4. Take a hypervisor snapshot

Both zabbix and proxy VMs.

## 5. Upgrade server and web

In the inventory, change `ubuntu-$OLD` → `ubuntu-$NEW` for `zabbix-server-pgsql` and `zabbix-web-nginx-pgsql`, then:

```bash
cd ~/projects/ansible-playbooks
.venv/bin/ansible-playbook -i "$INVENTORY" docker_compose_projects.yml -l zabbix.lan.chere.one --diff
```

On the zabbix host, in `$COMPOSE_DIR`:

```bash
docker compose logs -f --tail=100 zabbix-server   # "database upgrade fully completed", "server #0 started"
docker exec $DB_CONTAINER psql -U $DB_USER -d $DB_NAME -c "SELECT mandatory, optional FROM dbversion;"
docker compose ps
```

**STOP** on DB upgrade errors: restore the snapshot or the dump.

## 6. Upgrade proxy

After a major upgrade, an older proxy is "outdated": it collects data but gets no config updates. Change the `zabbix-proxy-sqlite3` tag in the inventory, then:

```bash
.venv/bin/ansible-playbook -i "$INVENTORY" docker_compose_projects.yml -l zabbix-proxy-nosova.lan.chere.one --diff
```

Check: Administration → Proxies → version is `$NEW`, no "outdated" mark, last seen updating.

## 7. Check for edits to stock templates

The import overwrites stock templates and deletes items/triggers missing from the official files. Customizations must live in own templates or host/wrapper macros. If unsure, export the stock templates and compare them by UUID with the official files of the `$OLD` tag (git.zabbix.com, `templates/`).

**STOP** if there are edits you want to keep: move them into own templates first.

## 8. Import stock templates

```bash
cd /tmp && rm -rf tb && mkdir tb && cd tb
curl -fLO https://www.zabbix.com/documentation/$NEW_MAJOR/assets/en/template_bundles/templates_bundles-$NEW_MAJOR-1M-nginx.zip
unzip -q templates_bundles-$NEW_MAJOR-1M-nginx.zip
rm media_bundle-*.yaml    # otherwise Email/Telegram settings are reset to placeholders
./import_templates.sh /tmp/tb "$ZBX_URL" "$ZBX_TOKEN" | tee /tmp/tb/import.log
grep -c 'Successfully imported' /tmp/tb/import.log
grep 'Import error' /tmp/tb/import.log
```

The script adds `/api_jsonrpc.php` itself and always exits 0, so check the log. Rerun on dependency errors; the import is idempotent.

To update a single webhook media type, import only its file from `templates/media/` in the `release/$NEW_MAJOR` branch (Alerts → Media types → Import), then re-enter its secrets.

## 9. Verify

- Reports → System information: server and frontend at `$NEW`, no warnings
- Monitoring → Latest data: new values on all hosts, including proxy-monitored ones
- Own templates still linked to their hosts
- Alerts → Media types: Email (HTML) enabled with the real SMTP server, Telegram token intact
- Send a test notification (Media types → Test)

## 10. Clean up

Once everything has worked for a few days: delete the pre-upgrade dump and the snapshots, and run `docker image prune` on both hosts.
